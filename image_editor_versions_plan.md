# План image_editor_versions

## Цель и исходные данные

Создать две локальные версии свадебного приглашения с выбором и кадрированием каждой фотографии. Исходные `index-a6.html`, `index-a6-3.html` и их стили сохранить без изменений. Каталог не является Git-репозиторием; ветка, HEAD и база отсутствуют.

Фактический источник вариантов — `assets/images_person`: 16 файлов `1.jpg`…`16.jpg`. Указанное в запросе имя `images_persons` трактуется как эта существующая папка.

## Требования и критерии приёмки

- Новые страницы `index-a6-editor.html` (пять фотографий) и `index-a6-3-editor.html` (одна фотография), с сохранением текста, оформления и размеров A6.
- Слева вне печатного листа — ровно один селект для каждой фотографии. Все 16 вариантов доступны в каждом селекте; исходная фотография доступна отдельной исходной опцией для полноценного сброса.
- Рядом с каждым селектом числовые настройки смещения X/Y и масштаба. Смещения измеряются в процентах размера кадра, масштаб — в процентах. Изменения применяются сразу и не меняют геометрию листа.
- Изображения вписываются в фиксированные кадры через cover без искажения пропорций; кадр обрезает выходящие части. Кадры наследуют форму и положение исходного макета.
- Смена изображения возвращает X/Y к 0 и масштаб к 100%.
- Справа вне листа — «Сбросить всё», «Экспорт JSON» и «Загрузить JSON». Сброс возвращает исходные фотографии и нулевые настройки.
- JSON содержит версию формата, идентификатор страницы и стабильные идентификаторы позиций, файл, X/Y и масштаб. Импорт проверяет весь документ до изменения страницы, отклоняет чужую страницу, неизвестные позиции/файлы и неверные числа с понятным сообщением.
- Повторная загрузка того же файла работает; экспорт скачивает обычный JSON. Работа через file:// без fetch, модулей, сервера и новых зависимостей.
- Печать скрывает панели и сохраняет A6.

## Файлы и реализация

1. Скопировать исходные HTML в два новых файла, подключить общие `image-editor.css` и `image-editor.js`, добавить идентификатор страницы и позиции изображений.
2. Сохранить исходные стили; в общем CSS добавить компоновку «панель — лист — кнопки», читаемые элементы управления и фиксированные кадры фотографий с overflow hidden. На узком экране сохранить панели слева/справа и разрешить горизонтальную прокрутку.
3. В JS собрать единственную конфигурацию 16 вариантов и состояние позиций из атрибутов HTML; построить селекты и числовые настройки. Не добавлять изображения-превью в панели, чтобы количество изображений страницы соответствовало позициям.
4. Применять выбранный src, object-fit и transform к изображению внутри кадра. Сбрасывать локальные настройки при смене выбора.
5. Реализовать общий сброс, скачивание JSON через Blob и импорт через FileReader/File.text с полной валидацией перед применением.

## Проверки

- Сверить количество img/селектов: 5 и 1; проверить наличие всех 16 файлов и подключённых ресурсов.
- Проверить синтаксис JavaScript через доступный Node.js, без установки пакетов.
- В доступном браузере проверить обе страницы, смену фото, X/Y/масштаб, локальный и общий сброс, экспорт и повторный импорт, отклонение некорректного/чужого JSON, отсутствие выхода фото из кадра и печатное скрытие панелей.
- Сверить SHA256 исходников с подготовкой: index-a6.html `4B082BD8B0B0A50D1F328FF72BA504EF101FE070A6B39B1F79AA8B54BAE4967A`; index-a6-3.html `987EDFE1A191A15DF476FB70E41E3D1EF74B00B5970BFDAF0A6385335BAAB5B5`.
- Не создавать тестовые файлы, не устанавливать зависимости и не запускать несуществующую сборку. Если браузерная проверка недоступна, явно указать это ограничение.

## Риски и решения

- Исходные стили используют прямые селекторы для hero img и позиционирование cover-photo: новые кадры получают явные размеры/слои в отдельном CSS, без изменения исходных стилей.
- Файловая страница не может перечислить папку автоматически: список 16 файлов задаётся в JS; при последующем добавлении фотографий список нужно дополнить.
- Сильные смещения и уменьшение масштаба могут открыть фон кадра — это ожидаемый результат ручной настройки; начальное кадрирование заполняет кадр.
- Экспорт относится к конкретной странице, чтобы настройки пяти позиций нельзя было случайно применить к обложке.

Открытых вопросов, блокирующих реализацию, нет.
